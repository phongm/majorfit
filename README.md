# 专业适配

> 不看你想成为谁，看你受得了哪种辛苦。

面向中国高中生的本科专业适配推荐系统。纯前端计算，答题内容不出你的设备。

**在线体验** · https://majorfit.mengyadiary.com

## 为什么和多数测评不一样

多数志愿测评（以及 MBTI、霍兰德那类工具）问的是「你喜欢什么」，然后按喜好推荐。这套系统按三条规则工作：

**1. 先问硬事实。** 选科组合、体检色觉、能接受的学制决定你能报什么。临床医学多数要求物理加化学，没选化学就直接出局——这时候兴趣契合没有意义。过滤先于排序，被挡掉的方向会单独列出来告诉你**是被什么挡住的**。

**2. 问做过什么，不问觉得自己是什么。** 选项全是能拿出证据的事实。不会问「你觉得自己有毅力吗」，而是问有没有一件持续两周以上、没人催着也做完了的事。自评特质在十八岁这个年龄的区分度很低，且几乎所有人都会往体面的方向答。

**3. 兴趣几乎不加分，代价才是主变量。** 课程负载超出你能忍受的程度，最多扣 45 分；兴趣契合，最多给 8 分。

第三条是整套系统的骨架，也是唯一一处我认为值得和别人吵的设计假设：**兴趣错配让人读得难受，代价错配让人读不完**。退学、延毕、转专业失败的人，多半是扛不住高数与实验课的密度，而不是发现自己不喜欢这个领域。所以引擎对「耐受缺口」做非对称惩罚，对「喜好」只做小幅奖励。

## 现在做到什么程度

| | |
|---|---|
| 题目 | 39 道（硬事实 8 · 行为证据 10 · 耐受度 12 · 取舍 9） |
| 专业 | 官方目录 988 个专业全部可过滤与浏览，其中 **67 个有人工画像**（覆盖 6.8%） |
| 测试 | 195 个，`npm test` 全绿 |
| 统计服务 | 代码写完了，但**线上没部署**：`worker/wrangler.toml` 的 `database_id` 还是注释掉的占位，`public/config.js` 的 `statsEndpoint` 为空。所以你答题不会有任何东西上传 |

明确没做的：

- **院校层次**。同一个计算机科学与技术，985 和双非的校招出口是两个世界。这个变量在多个条目的 `todo` 里挂着，还没进模型。
- **省份分数线与招生计划**。这里判断的是「适配」，不是「你能考上」，后者要用志愿卡的数据。
- **学费逐校核实**。中外合作与民办差异可达 1.5 万+/年，缺省按公办普通收费计。
- **67 条以外的专业**。它们靠 `src/data/profiles/derive.ts` 从已核对样本按专业类聚合出推断值，只服务浏览与自选诊断，**没有资格进推荐**——推断层不发明判断，但也不该被当成判断。

## 评分怎么算

```
硬过滤（选科 / 色觉 / 学制 / 通道）
   ↓
耐受缺口非对称惩罚  −45 … 0      只罚「专业要求 > 你的耐受」的正缺口，幂函数放大
   ↓
兴趣契合            +0 … 8
价值观吻合          +0 … 6
就业兑现度          +0 … （undergradJobFit / 深造依赖 / 考公可报性 / 行情趋势）
   ↓
排序 + 解释（每条理由都指向具体题号与具体课程）
```

常量集中在 `src/engine/rank.ts`，可以直接读：`LOAD_CAP = 45`、`LOAD_K = 19.6`、`LOAD_EXPONENT = 1.7`、`INTEREST_BONUS = 8`、`VALUE_BONUS_CAP = 6`。

负载向量有 11 维（数学、编程、抽象、记忆、实验、视觉、写作、定量、人际、野外、体力），每个专业逐维打分。**11 维全部必填**，因为引擎把缺失当 0，一个漏填高记忆量的专业会被静默推给背不动的学生。

专业在该项要求很高、而你没测出耐受度时，界面必须显式标红旗，而不是按 0 处理。

## 数据来源与可复现

数据分两层，性质不同。

**目录层**（`src/data/catalog/2026.ts`）来自教育部《普通高等学校本科专业目录（2026年）》，教高函〔2026〕2号，2026-04-07 印发。原始 PDF 存档在 `scripts/source/`，带 sha256 校验值与抓取日期，重新生成：

```bash
npm run build:catalog   # 从 PDF 重放，产物可 diff
```

这一层只有事实字段：代码、名称、所属专业类、学位授予注记（T 特设、K 国家控制布点）。

**画像层**（`src/data/majors/`）是人工判断，不是数据。负载向量、RIASEC、负面清单、行情趋势都是我做的取舍，每条带 `todo` 说明哪一栏还没核实、置信度自动降级。界面上的「凭什么这么说」会区分**人工核对**与**类级推断**两种来源。

判断会错。这是我把它开源而不是藏起来的原因——见 [CONTRIBUTING.md](./CONTRIBUTING.md)。

## 隐私设计

- 答题内容只存在浏览器本地，不上传
- 服务器只收到几个数字：有人打开、有人开始答、有人答完、推荐了哪几个专业
- 会话号是随机 UUID，存 sessionStorage，关页面即失效，不落 cookie、不做设备指纹
- 色觉、视力这类体检字段只参与本地计算，永不上传
- 上报字段是白名单校验的。**答题内容在服务端数据结构里根本没有对应字段**——不是「承诺不存」，是「存不进去」

服务端拿到的 `picks`（用户自选清单里的专业代码）是唯一能指出「哪些专业的画像判断错了」的数据来源，
内容被收紧成 `[0-9]{6,7}(TK|T|K)?$`，不含专业名称以外的用户输入。

## 目录结构

```
src/
  assessment/     # 题库、schema、评分（39 题）
  data/
    catalog/      # 官方目录生成物，不要手改
    majors/       # 67 条人工画像 ← 最需要外部贡献的部分
    profiles/     # 类级/门类级推断，只服务浏览
  domain/         # 类型、招录通道、体检限制
  engine/         # 过滤、排序、解释
  ui/             # React 组件
  analytics/      # 埋点客户端与事件白名单
  wishlist/       # 自选清单

server/           # Node 统计服务（方案一）
worker/           # Cloudflare Worker + D1（方案二）
deploy/           # Nginx、systemd、日志备份
tests/            # 含数据完整性门与文案门
```

## 本地开发

```bash
npm ci
npm run dev         # http://localhost:5173
npm test
npm run typecheck
npm run build
```

需要 Node 22+。**只有跑统计服务（`npm run stats`）要求 Node 23.6+**：`server/index.ts` 直接以 TypeScript 运行，依赖 Node 原生的类型剥离。

用 pnpm 也行，两把 lockfile 都在仓库里（`pnpm-lock.yaml` 是 Cloudflare Pages 识别包管理器用的，别删）。

`tests/wording.test.ts` 是文案门——它拦空断言、拦没有中文解释的英文术语、拦界面里泄漏内部题号、拦引用不实的选项原文。改文案前先看它，比被我驳回快。

## 部署

[DEPLOY.md](./DEPLOY.md) 给两种方案：

| | 方案一：自有服务器 | 方案二：Cloudflare Pages + Cloudflare Worker |
|---|---|---|
| 成本 | VPS 约 30–50 元/月 | 免费（额度内） |
| 运维 | Nginx + systemd | 零 |
| 域名备案 | 需要 | 不需要 |
| 数据 | 日志在自己机器 | 在 Cloudflare |
| 大陆访问 | 快 | 境外，可能慢 |
| 适合 | 面向大陆用户 | 快速上线、海外 |

自架统计服务前请看 DEPLOY.md 第九节的隐私边界确认清单——尤其是 `comments` 字段，用户会自行写入姓名、学校、考号。

## 许可

MIT，代码与数据都是。你可以 fork 出去做自己的志愿工具、把它接进商业产品、改全部判断值，不需要授权也不需要付费。

唯一想要的是：**如果你认为我的某个专业判断错了，请提回来。** 67 条画像对着 988 个专业，这个系统只有靠很多人往里填才成立，而封闭维护它没有意义。

## 免责声明

这不是升学规划服务，给不出「能不能考上」的答案，也不了解你的具体情况。专业判断部分是有立场的意见，不是事实。
最终决定请结合目标院校培养方案、你们省招生办意见和孩子自己的意愿。
界面里所有推荐都带得出处的说法，是为了让你能反驳它，而不是为了让你信它。
