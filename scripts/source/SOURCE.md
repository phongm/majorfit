## 为什么同时存 txt

`catalog-2026.txt` 是 `pdftotext -layout` 的输出。生成脚本只读这份文本，不依赖 PDF 解析库，
换机器也能重跑；PDF 留在库里是为了能随时重新提取并核对 SHA-256，防止文本被误改。

```sh
pdftotext -layout scripts/source/普通高等学校本科专业目录（2026年）.pdf \
  scripts/source/catalog-2026.txt
npm run build:catalog
```

## 每年更新流程

1. 下载新一年目录 PDF，替换 PDF 与 txt，更新本文件的文号、URL、SHA-256、抓取日期；
2. 更新 `scripts/build-catalog.mjs` 里的 `METADATA`、`FIELD_KEYS`（若门类有增删）和 `expected` 数量；
3. `npm run build:catalog` —— 数量或归属对不上会直接报错，不会静默产出半个目录。

## 官方目录里**没有**的东西（别指望从这里拿）

- **学制**：目录说明第五条写明修业年限由高校设置专业布点时确定，所以 `degreeYears` 不能从目录导入；
- 学位授予年限、招生省份计划数、选科要求（选科要求另见《选考科目要求指引》，按专业类给口径）；
- 任何关于课程强度、就业兑现、负面清单的判断 —— 这些是画像层的录入内容，不是目录内容。
